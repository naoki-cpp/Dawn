# ADR-0020 — Simulation LoD（非交戦エンティティの休眠化）

> **ステータス注記**: 本 ADR は **deferred（見送り）**（2026-06-15）。設計は妥当だが、
> 着手前のコストモデル検討で「計算メリットが未実証かつ条件付き」と判明したため、現フェーズでは実装しない。
>
> **見送り理由（計算コストの観点）**:
> - ADR-0019 で確定した通り、**サーバ計算側に O(n²) は存在しない**。1 Tick の計算は小さい定数 c の
>   **O(n)**。LoD が削るのはその n を k（交戦数）に縮める **c·(n−k)** のみ。
> - 非交戦船 1 隻の毎 Tick コストは極小（Movement の `pos+=vel` と cap recharge。Lock/Combat は早期スキップ）。
>   ゆえに節約が予算（16ms）に効くのは **idle ≫ active かつ n が極大**のときに限られ、純粋密戦闘では
>   k≈n で**節約ゼロ**（そこは TiDi の領分）。
> - さらに「どの船が Dormant か」を毎 Tick 全走査で判定すると**それ自体が O(n)** で相殺し得る。
>   回避には増分分類（イベント駆動の昇格／降格）が要り、閉包・遅延状態・ヒステリシス・スナップショットの
>   複雑さを全て背負う。
> - 本当に O(n²) で高コストだった **AoI 配信（ADR-0019 / 8C）は実装済み**。LoD が攻めるのは O(n) であり、
>   大掛かりな機構で O(n) を削るのは c が大きいか n が極大のときだけ正当化される。
>
> **再開条件（go/no-go スパイク）**: 現状実装のまま、active な小戦闘（k 固定）の周囲に非交戦船 n を
> 1k→50k→100k と増やして 1 Tick 時間を測り、**idle 反復が予算の有意な割合（例: 8ms 超）を占めて**
> いる場合にのみ本 ADR を `accepted` に上げて実装する。1–2ms 程度なら TiDi+AoI で足りるため
> 見送りを維持する。8B-1 で確立した「観測できない前提の上に作らない」規律を踏襲する。
>
> 以下は再開時にゼロから議論し直さないための**設計記録**である（実装は伴わない）。
> CLAUDE.md の不変条件の改訂は伴わない。新クレートは作らず Dependency DAG を変更しない。

## 背景

ADR-0018 は過負荷対応をヒエラルキー化した（分割 → **LoD** → 局所 TiDi → 入場制限）。
このうち局所 TiDi（8B-4..7）と入場制限（8B-1・生カウント）は実装済み、AoI（ADR-0019 / 8C）で
**配信側の容量**は上げた。残るのが **サーバ計算側の容量**を上げる本命のレバー = LoD（8B-3）である。

8B-1 で「アクティブ船除外（実効人口）」案を却下したとき、放置船を安くする効果は
**「数から除外」ではなく LoD の忠実度低下で表現する**と明示的に本 ADR へ委譲した。

### LoD が解く問題: 密戦闘のコストを「居住済み宇宙の残り」から隔離する

柱①（TiDi 閾値が EVE より桁違いに高い大規模戦闘 / ADR-0016）で効くのは「1 ゲート前の単一密戦闘」。
**空間分割（ADR-0019 / Fission）は密戦闘そのものには効かない**（全員が同一近傍に入る）。
だが密戦闘が起きている同じ Sector には、その戦闘に**参加していない**大量のエンティティもいる
（遠方の放置船、移動中の単独 NPC、別空域の船）。

現状、毎 Tick の各システム（Movement / Capacitor / Lock / Combat）は **全船を反復する**。
10 万の非交戦船 + 5 千の交戦船がいれば 10.5 万体を毎 Tick 触る。LoD の狙いは:

> **交戦している船にだけ毎 Tick の計算予算を使い、非交戦船は反復対象から外す。**
> 密戦闘の実コストを n（Sector 総数）から k（実際に相互作用している数）へ落とす。

これにより単一 Sector の容量＝ TiDi 閾値が上がる（柱①）。**TiDi を不要にはしない**:
k 自体がノード容量を超える純粋な密戦闘は依然 TiDi に落ちる（ADR-0019 と同じ立場）。

---

## 決定

### 1. 忠実度は「距離」ではなく「相互作用」で決める。近似はしない（交差閉包）

game-design.md §8 は 高/中/低 の 3 段階を素描していたが、それは AoI 実装前・かつ
「中忠実度 = N Tick に 1 回」という**近似**を含んでいた。本 ADR はそれを近似ゼロの **2 段階**に絞る。

```
Active（高忠実度） : この Tick に相互作用しうる船 → 毎 Tick 完全処理（現状どおり）
Dormant（休眠）    : 相互作用せず、状態遷移が経過 Tick の閉形式関数である船
                     → システム反復から除外。位置・cap は遅延計算（参照時にまとめて積分）
```

**判定は ECS の状態から導く（新イベント不要）**:

```
Active であるための十分条件（いずれか）:
  - LockComp にエントリがある（ロックしている／されている）
  - 自分を locked している船が存在する（被ロック = 撃たれうる）
  - 有効化済みモジュールがある（cap を消費している／武器サイクル中）
  - 速度が一定でない（推力で加速・減速中 = ApproachComp / 直近 Move/Stop）
  - 直近 K Tick 内にプレイヤーコマンドを受けた（操作中）

Dormant の必要条件（全て満たす）:
  - LockComp が空・被ロックなし・有効モジュールなし
  - 速度が一定（ゼロ含む）→ 位置は position(t) = p0 + v·(t − t0) の閉形式
  - cap は cap(t) = min(cap_max, c0 + recharge·(t − t0)) の閉形式
```

### 2. 近似ゼロ — Dormant の遅延計算は「間引き」ではなく「厳密な閉形式評価」

EVE の LoD は遠方の更新を**間引いて近似**する。本 ADR の Dormant は**近似しない**:

- INV-MOVE（ADR-0008）により位置は `position += velocity` の純粋算術。速度一定なら
  N Tick 分を `p0 + v·N` と一括評価しても**毎 Tick 積分と完全に一致**する（決定論・INV-002 維持）。
- cap recharge も同型の線形関数。`min(cap_max, …)` の飽和も閉形式。
- ゆえに Dormant 船は「処理を省く」が「結果は省かない」。参照時（クライアント配信・スナップショット・
  Active への昇格・近傍探索の被参照）に経過 Tick から厳密に再構成する。

これは EVE より誠実な差別化: **休眠させても世界は一切ぼけない。**

### 3. 交差閉包の不変条件（LoD-CLOSURE）— これが安全性の核

```
LoD-CLOSURE: Dormant 船の（遅延された）状態は、いかなる Active 船のその Tick の
             計算の入力にもなってはならない。
```

成り立たせ方は **昇格規則**で閉じる:

- Active 船が新たに別船をロック／接近／AoE 範囲に収めた瞬間、その対象を**先に昇格**してから処理する。
- 被ロックされた船は定義上 Active（上記条件）。よって「撃たれる側」は必ず Active で、遅延位置のまま
  撃たれることはない。
- Dormant 船同士は相互作用しない（どちらもロック・武器なし）。
- 結論: Active 集合は「相互作用しうる船」で**閉じている**。Dormant 船の遅延状態が戦闘結果・因果に
  影響する経路が存在しない。

この閉包があるため、各システムを Active 集合だけで反復しても**全船反復と同一の結果**になる
（§6 の処理順序は不変・反復対象だけが縮む）。

### 4. クライアント側デッドレコニングと整合する（配信も 0 になる）

Dormant 船は速度一定 → INV-MOVE により VelocityChanged を**出さない** → AoI（ADR-0019）でも
新規イベントが流れない。クライアントは既存の等速外挿（dead reckoning）で位置を描き続ける。
速度が変わる＝昇格＝ VelocityChanged 発火＝クライアントが更新を受ける。
**Dormant はサーバ計算 ~0 かつ帯域 ~0 で、見た目は正しいまま。** AoI と LoD が噛み合う。

## 単一密戦闘では LoD も最後は TiDi に落ちる（重要）

LoD が削るのは**非交戦**船である。3000 人全員が相互ロック・相互射撃する純粋密戦闘では、
全員が Active になり k ≈ n、コストは戻る。そこは ADR-0018 の局所 TiDi に落ちる（ADR-0019 と同じ）。
**LoD は「戦闘の周りの宇宙」を無料化して閾値を押し上げるが、戦闘の芯は TiDi が受け持つ。**

## 代替案

- **3 段階（高/中/低・中 = N Tick に 1 回の物理更新 / game-design §8 素描）**: 中忠実度は加速中の船を
  間引く＝**近似**で、LoD-CLOSURE 下でしか安全でなく、決定論に微小誤差を持ち込む。AoI 実装後は
  クライアント外挿が等速を吸収するため中段の必要性も薄い。**近似ゼロの 2 段階**を採り、中段は
  「必要が実証されたら」の将来拡張に留める（下記スコープ外）。
- **距離ベースの忠実度（観測者から遠い船を間引く）**: 「遠いが交戦中」を誤って間引く／「近いが放置」を
  無駄に処理する。相互作用ベースの方が正確で、AoI（距離=配信）と責務が重複しない。却下。
- **タイムスライス（全船を r 分割し毎 Tick 1/r だけ更新）**: 一律近似で密戦闘の精度を落とす。
  交戦船こそ毎 Tick 必要なので逆効果。却下。
- **LoD を入れず Fission に頼る**: Fission は密戦闘に効かない（§背景）。密戦闘の容量は上がらない。却下。
- **LoD を別クレート化**: 反復対象の選択は ECS（`dawn-ecs`）とシステムに密。新クレートの利得なし。見送り。

## スコープ外（本 ADR では決めない）

- **中忠実度（近似 N-Tick）段の導入**: Active 集合（＝加速中だが非交戦の単独船を含む）がベンチで
  過大と判明した場合にのみ、LoD-CLOSURE 下の近似段として別途検討する。まずは近似ゼロで測る。
- 降格までの猶予 K Tick・ヒステリシスの具体値 — 実装時にベンチで決める（フラッピング防止）。
- Dormant 船の空間索引（昇格時の近傍探索）— ADR-0019 の静的セルを再利用する（新規構造は作らない）。
- Sector の動的分割（Fission / 8B-2）・差分 TiDi 越境（8B-8）— 別 ADR。
