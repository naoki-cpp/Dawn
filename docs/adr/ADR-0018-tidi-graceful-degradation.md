# ADR-0018 — Time Dilation の境界つき局所採用

> **ステータス注記**: 本 ADR は CLAUDE.md（権威ある運用規約）の INV-TiDi 反転・§1 原則6・
> ADR-0016 柱①の言い換えを伴う。人間の承認を得て CLAUDE.md §1/§2・tick-model.md §8・
> ADR-0016 柱①に適用済み（2026-06-14）。
> なお dilation 係数の適用・SLA 記録などの**コード実装は未着手**（下記チェックリスト参照）。
> 本 ADR は方針確定であり、実装は別タスクで段階的に行う。

## 背景

eve-reference.md §11.1 の批判と、人間オーナーの判断
**「TiDi はなるべく起きないようにしつつ採用してもいい」** を反映する。

旧 INV-TiDi は「論理 Tick 速度は**常に**一定。TiDi は禁止。過負荷は入場制限と動的分割で**事前**に対処」だった。
§11.1 が指摘した問題:

- **単一密戦闘は原理的に分割不能**。3000 人が一点で戦うとき、動的分割は戦闘そのものを割らない限り効かない。
- すると旧設計の手段は**入場制限**のみになる。だがそれは「クライマックスの戦いに入れない」を意味し、
  EVE の TiDi（全員が遅いが**参加できる**）より**むしろ悪い**可能性がある。
- 「入場制限 vs TiDi のどちらが良いか」は自明でないのに、旧設計は一方的に断じていた。

### 重要な気づき: TiDi は INV-005 を壊さない

TiDi ＝「論理 Tick 1 つに費やす**実時間**を伸ばす」ことであり、論理 Tick の単調増加・決定性は保たれる。
因果順序は論理 Tick で決まる（INV-005）ため、TiDi は INV-005 とも ADR-0017 の決定性とも**無関係**。
TiDi が触るのは INV-TiDi だけで、**採用はクリーンにできる**。
TiDi がやってはいけない唯一のことは「論理結果を変えること」— TiDi は**純粋な実時間ペーシング**に留める。

## 決定

### 1. 負荷対応をヒエラルキー化する

過負荷への応答を、負荷の性質で使い分ける。TiDi は**最後の安全網**として加える。

| 状況 | 第1手 | 第2手 | 最終バックストップ |
|---|---|---|---|
| 空間的に分離可能な負荷 | **動的 Sector 分割**（劣化ゼロ） | — | — |
| 単一密戦闘・負荷上昇 | **LoD**（遠方/非戦闘の更新間引き） | **局所 TiDi**（全員残る） | **入場制限** |

旧設計との本質的な差: **単一密戦闘では入場制限が「最後」に下がる**。
まず LoD、次に局所 TiDi（全員が遅いが参加できる）、それでも遅延を許容内に保てない極端時にのみ入場制限。
「入れない」より「全員が少し遅い」を優先する。

### 2. INV-TiDi を改訂する（CLAUDE.md §2）

```
INV-TiDi（改訂案）:

論理 Tick 速度は通常負荷下では一定に保つ。
Time Dilation（論理 Tick の単調性・決定性を保ったまま、実時間ペースのみを落とす）は、
分割不能な単一ホットスポットがノード容量を超えた場合に限り、
次をすべて満たす「境界つき最終手段」として許可する:

  (a) 局所性   : dilation は当該 Sector に限定する。隣接 Sector へ伝播させない。
  (b) 観測可能 : dilation 係数・継続時間を SLA イベント / メトリクスとして記録する。
  (c) 非破壊   : イベントの並べ替え・欠落・結果変化を起こさない（純粋な実時間ペーシング）。
  (d) 自動回復 : 負荷が引いたら係数を 1.0 へ戻す。
  (e) 発動順序 : 分離可能な負荷は動的分割で劣化ゼロに。単一密戦闘では LoD → 局所 TiDi の順。
                 入場制限は TiDi でも遅延を許容内に保てない極端時のみの最終バックストップ。

違反例（改訂後も禁止）:
  - dilation でイベントを間引く / 並べ替える（決定性破壊・INV-002 / INV-005 違反）
  - 物理時刻で dilation を判定する（INV-005 違反。判定は論理 Tick の処理予算超過で行う）
  - 全 Sector を一律に dilate する（EVE 型。局所性 (a) 違反）
  - dilation 中であることを記録しない（観測不能。(b) 違反）
```

### 3. EVE との差別化は「無 TiDi」から「桁違いに高い閾値 + 局所・短時間」へ

EVE は各ノード＝1 Python コアのため **TiDi が早期かつ広域**に出る。
dawn は Rust + マルチコア + 空間索引 / AoI（別 ADR 予定）で**閾値を桁で上げ**、
TiDi を**当該 Sector 局所**に留め、**観測可能**にし、**自動回復**する。
これは「TiDi が無い」より誠実で、差別化としてはむしろ強い。

- **ADR-0016 柱①の言い換え**: 「TiDi の無い大規模リアルタイム戦闘」→
  「**TiDi 閾値が EVE より桁違いに高く、出ても局所・短時間・自動回復する**大規模リアルタイム戦闘」。
- **§1 原則6 の言い換え**: 「Tick の論理速度は一定。入場制限で対処し Tick を遅らせない」→
  「Tick の論理速度は通常一定。過負荷は**分割 → LoD → 局所 TiDi → 入場制限**の順で対処する」。
- **§1 競争優位の記述**: 「アンチ TiDi — 大規模戦闘でも論理 Tick を一定に保つ」→
  「アンチ TiDi — TiDi 閾値を桁違いに高く保ち、出ても局所・短時間に抑える」。

### 4. 閾値を上げる本体は別 ADR（空間索引 + AoI）

TiDi を**稀**にするのは §4 の空間索引 + AoI + ロックグラフ戦闘（O(n²)→O(n·k)）であり、別 ADR で扱う。
**B（天井↑）が効くほど本 ADR の TiDi 発動が減る**という連動関係にある。
本 ADR は「天井を上げきれなかったときの安全網」を定義するもので、B の代替ではない。

## 未解決の論点（正直に）

### 差分 TiDi の越境因果

Sector A が 0.3 倍に dilate、隣接 B が等速のとき、A→B を transit する船は時間レートの不連続に当たる。
A 由来のイベントが B 視点で「実時間で引き伸ばされて」到着する。

- 論理 Tick が真実（INV-005）なので**原理的には壊れない**: 越境は「論理 Tick で同期、実時間は受信側ペースで吸収」。
- ただし実装規則として明文化が必要（どの Tick で所有権が flip するか、dilation 中の transit を許すか等）。
- **本 ADR では方針のみ**: 「越境の整合は論理 Tick で取る。実時間ペースの差は表示層が吸収する」。
  具体は TiDi 実装 ADR / Phase 8 で詰める。今は INV-TiDi の (a) 局所性で隣接伝播を禁じることで安全側に倒す。

## トレードオフ（正直に）

- **TiDi は全員を等しく遅くする**。これは「一部を締め出す」より公平だが、依然として劣化である。
  「無劣化」ではない — 無劣化は分割可能な負荷でしか達成できない。
- **入場制限を捨てたわけではない**。最終バックストップとして残す。TiDi でも実時間遅延が
  プレイ不能域に達するなら、新規入場を絞るしかない局面はある。
- **dilation 係数・SLA の観測基盤**を持つ必要がある（決定 §2 (b)）。実装コスト増。
- **越境因果の規則**を将来詰める負債を負う（上記未解決）。局所性 (a) で当面は安全側。

## 却下した代替案

- **旧 INV-TiDi 維持（絶対アンチ TiDi）**: 単一密戦闘で手段が入場制限のみになり、
  クライマックスの戦いから締め出す。EVE の TiDi より悪い体験になりうる（§11.1）。却下。
- **EVE 型グローバル TiDi**: 全 Sector 一律・早期発動。dawn の局所性・高閾値の利点を捨てる。却下
  （局所・最終手段に限定する）。
- **入場制限を完全撤廃し TiDi のみに頼る**: TiDi でも実時間遅延が無限には吸収できない。
  極端時のバックストップは必要。却下（入場制限は最終手段として残す）。
