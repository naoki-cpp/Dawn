# ADR-0012 — タレット追跡メカニズム

## 背景

従来の戦闘システムでは、タレットのダメージが毎サイクル無条件に適用されていた。
ロック済みのターゲットは、距離・速度・接近角度に関わらず常にフルダメージを受けていた。

これにより戦闘は一次元的になっていた。
敵のロック射程外でカイトするだけが唯一の防御手段であり、
ポジション管理・オービット距離・トランスバーサル速度を意識する理由がなかった。

EVE Online はこの問題を、よく知られたタレットモデルで解決している。
詳細は https://wiki.eveuniversity.org/Turret_mechanics を参照。
核心的な洞察は「タレットは有限の角速度追跡能力を持つ」という点にある。
砲身が回転できるより速くターゲットが横切ると、命中が困難になる。

参考: EVE University wiki "Turret mechanics"（2026-06-09 参照）

---

## 決定事項

### 1. 命中率の計算式

EVE Online の計算式をそのまま採用する。

```
命中率 = 0.5 ^ ( 追跡項^2 + 射程項^2 )

追跡項 = 角速度 / (追跡速度 × シグネチャ半径)
角速度 = トランスバーサル速度 / 距離

射程項 = max(0, 距離 - 最適射程) / フォールオフ
```

**特性一覧:**

| 条件 | 命中率 |
|---|---|
| 静止ターゲット・最適射程内 | 1.0（必中） |
| 角速度 = 追跡速度 × シグネチャ半径 | 0.5 |
| 距離 = 最適射程 + フォールオフ | 0.5 |
| 距離 = 最適射程 + 2 × フォールオフ | 0.0625（6.25%） |
| 純粋な正面アプローチ（トランスバーサル = 0） | 追跡項 = 0 → 射程のみが影響 |

追跡と射程は指数内で独立した軸として機能する。
近距離でも高速なターゲットは、遠距離の低速ターゲットより当てにくくなる場合がある。

### 2. 新規パラメータ

#### 船体: `sig_radius`（ShipBaseStats + ShipStatsComp）

船体のシグネチャ半径。大型船ほど追跡されやすく当てやすい。

| 船クラス | デフォルト sig_radius |
|---|---|
| Magpie（フリゲート） | 35 |
| NPC フリゲート | 40 |
| NPC デストロイヤー | 60 |
| NPC クルーザー | 125 |

今回の実装ではモジュールによる変更不可。
（将来: アフターバーナーは sig_radius を増加させるペナルティを持つ、シグネチャダンプナーは減少させる）

#### モジュール: `tracking_speed_add`（StatDelta）

1 つの武器モジュールが提供する rad/tick 単位のタレット追跡速度。
`apply_fitting()` を通じてアクティブ全武器モジュールの値が加算集計される。

| モジュール | tracking_speed_add |
|---|---|
| Small Railgun I | 0.035 rad/tick |
| Medium Railgun I | 0.020 rad/tick |
| Heavy Railgun I | 0.008 rad/tick |

**数値の根拠:**

Small Railgun vs Magpie（sig=35）が距離 1000 u で 500 u/tick オービット中:
- トランスバーサル ≈ 500、距離 = 1000 → 角速度 = 0.5 rad/tick
- 追跡項 = 0.5 / (0.035 × 35) = 0.408
- 命中率 = 0.5^(0.408²) ≈ 0.89 — 1000 u では十分に当たる

同条件で距離 300 u（近距離オービット、タックル射程の典型値）:
- 角速度 = 500 / 300 = 1.67 rad/tick
- 追跡項 = 1.67 / (0.035 × 35) = 1.36
- 命中率 = 0.5^(1.36²) ≈ 0.34 — 当てにくい。近距離オービットが実質的な回避手段になる

Heavy Railgun vs 同 Magpie（距離 1000 u）:
- 追跡項 = 0.5 / (0.008 × 35) = 1.79
- 命中率 = 0.5^(1.79²) ≈ 0.11 — スナイパー武器は高速フリゲートを追跡できない

#### モジュール: `falloff_range_add`（StatDelta）

1 つの武器モジュールが提供するフォールオフ射程（単位）。

| モジュール | falloff_range_add |
|---|---|
| Small Railgun I | 1000 u |
| Medium Railgun I | 1500 u |
| Heavy Railgun I | 2000 u |

### 3. ダメージ倍率

命中した場合、ランダムなダメージ倍率を適用する（EVE 互換）:

```
x = rand(0, 1)
倍率 = x < 0.01 の場合: 3.0    // 1% のラッキーショット（"wrecking shot"）
      それ以外:          x + 0.49  // 一様分布 [0.49, 1.49)
```

期待ダメージ ≈ 0.99 × mean([0.49, 1.49)) + 0.01 × 3.0 ≈ 基礎ダメージの 1.02 倍。

実際のダメージは `DamageTaken.damage` に格納されるため、
イベントログのリプレイはシミュレーション時の RNG シーケンスに依存せず正確に再現できる。

### 4. ミス処理

`rand(0,1) > 命中率` の場合、ショットはミスする。
ミスの場合は `WeaponFired` イベントを発行しない。
キャパシタはサイクルが発動した時点で消費済みのため、ミスでも消費される。

将来: クライアント側のフィードバック用に `WeaponMissed` イベントを追加する予定。
（「Miss!」テキスト、かすりエフェクトなど）

### 5. サイクルタイミングへの影響なし

追跡は命中率の修飾子にすぎない。
キャパシタサイクルシステム（ADR-0011）は変更なし:
武器はサイクル開始時にキャップを消費し、戦闘をトリガーする。
追跡は発射レートに影響しない。

## 実装詳細

### コンポーネントとデータモデル

```
dawn-core/src/ship_type.rs
  ShipBaseStats
    + sig_radius: f32

dawn-core/src/fitting.rs
  StatDelta
    + tracking_speed_add: f32
    + falloff_range_add:  f32

dawn-ecs/src/components/movement.rs
  ShipStatsComp
    + weapon_tracking: f32   (tracking_speed_add から集計)
    + weapon_falloff:  f32   (falloff_range_add から集計)
    + sig_radius:      f32   (ShipBaseStats から取得、delta ではない)
```

### 戦闘システムの変更

`dawn-ecs/src/systems/combat.rs`

- スナップショットに `position: Position` と `velocity: Velocity` を追加。
- `calc_hit_chance(attacker, target) -> f32` で上記計算式を実装。
- `damage_multiplier(rng) -> f32` でランダム倍率を返す。
- 命中率に対するランダムロールがダメージ適用の条件となる。

### データファイル

`data/ship_types.toml` — 全船種に `sig_radius` を追加。
`data/modules.toml`    — 全武器モジュールに `tracking_speed_add` と
                         `falloff_range_add` を追加。

## 影響

**ポジティブな影響**
- 近距離オービット中のフリゲートは大口径武器でほぼ当たらなくなり、
  ポジション管理が実質的な意味を持つようになる。
- 長距離スナイパーはターゲットを選ぶ必要がある:
  大型低速クルーザーは狙いやすいが、高速フリゲートはほぼ免疫に近い。
- 正面からの頭突き（ラジアルアプローチ）は攻撃側に命中率の優位をもたらし、
  交戦前からポジション判断が重要になる。
- EVE Online で実績のある計算式のため、プレイヤーも開発者も期待値を理解しやすい。

**ネガティブな影響・リスク**
- `sig_radius` はまだモジュールで変更できない。
  アフターバーナーは sig_radius を増加させるトレードオフを持つべきだが、未実装。
- ダメージが確率的になった。正確なダメージ値を断言するテストは、
  最小倍率でもキルが確定する大きなダメージ値（例: 99999）を使う必要がある。
- RNG は `thread_rng()`（シード固定なし）。
  リプレイはイベントに保存された実測値を使うため正確（INV-002 準拠）だが、
  同一シミュレーションを 2 回走らせると異なる命中パターンになる。

## 却下した代替案

### A. フラットな命中率パーセント

武器ごとに単純な `accuracy: f32` を持たせる方式は調整が容易だが、
角速度を使うシステムが生み出すポジション上の駆け引きを失う。
オービット距離とトランスバーサル速度を戦術的に意味のあるものにするには
角速度ベースの計算が不可欠。

### B. 「ミス」イベントの発行

`WeaponMissed` イベントを発行する案は検討したが、今回は保留とした。
クライアントにそれを表示する UI が実装される前に
イベントスキーマを複雑化させる理由がないため。
戦闘フィードバックのビジュアル実装時に再検討する。

### C. 船ごとではなく砲ごとの追跡

EVE では各タレットが独自の追跡速度を持つ。
Dawn では 1 船が 1 サイクルで 1 回のみ発射する（装備された砲の数によらず）ため、
アクティブな全武器モジュールの合計値として `weapon_tracking` を 1 つにまとめている。
フィッティングモデル全体と一貫した意識的な簡略化である。
