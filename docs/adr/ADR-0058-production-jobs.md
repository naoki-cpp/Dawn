# ADR-0058 — Production tiers

## 背景

### 今の生産には判断が無い

`BuildPackagedShip` は実装済みだが、実測値を並べると設計として空である。

| | 値 | 出典 |
|---|---|---|
| 撃破 1 隻の報酬 | Scrap Metal 1 | `node/tick.rs:24` `SCRAP_METAL_PER_SHIP_DESTROYED` |
| 建造コスト | Scrap Metal 1（**船種に依らない**） | `node/station_materialization.rs:15` `SCRAP_METAL_COST_PER_PACKAGED_SHIP` |
| 建造可能な船体 | 1 種類（`Magpie`）だけ | `data/ship_types.toml` `buildable = true` |
| 所要時間 | 即時 | 同上 |
| 同時実行数 | 無制限 | 同上 |

選べる船体が 1 種類、コストが一律、時間もかからない。`docs/design/game-design.md`
の中心原則「その機能はプレイヤーが意図的な判断を下す機会を増やすか？」に対して、
現状の生産の答えは **No** である。加えてコスト定数が船種に依らないため、
建造可能な船体を 2 種類目にした瞬間に破綻する。

### 絞り方の選択肢が限られている

`docs/design/game-design.md` §5 が **`（非交渉的）`** としているもの:

- 採掘は実装しない（「採掘している人はゲームをしていない」）
- スキルポイントによる成長は実装しない

EVE の産業が使う throttle のうち、採掘と放置収集は最初から使えない。

製造待ち時間は非交渉的ではない（§2「❌ 避けるべき悪い点」の教訓であって禁止事項
ではなく、採掘・スキルポイントとは階層が違う）。ただし教訓が指しているのは時間
そのものではなく、**プレイヤーが何も決めていない時間**である。

### ブートストラップの制約

プレイヤー設置インフラ（9C）を生産の前提にはできない。**構造物自体が生産物**
なので、それを作る場所が先に要る。加えて船も拠点も失ったプレイヤーがループへ
戻れないと、「実損のある危険な宇宙」（ADR-0016 柱④）が「一度負けたら終わり」
に変質する。

現状この前提は満たされている。`data/galaxy.toml` にあるのは `[[npc_stations]]`
のみで、ステーションに所有者の概念がそもそも存在しない。ADR-0034 の却下案にも
NPC 提供だけを先に置いたのは意図的である旨が記録されている。

## 決定

**Item に生産 Tier を導入し、NPC ステーションで作れるのは T1 に限る。T1 は所要
時間を持たない。**

### 1. Tier は「生産要件の区分」

| | T1 | T2 以降 |
|---|---|---|
| 生産場所 | どこでも（NPC ステーション含む） | プレイヤー設置インフラのみ |
| 所要時間 | **無し**（即時） | 有り（9C が決める） |

**Tier はレシピ（作り方）の属性であって、アイテムの属性ではない。** 上の表が区別して
いるのは「どこで作れるか」「どれだけ時間がかかるか」であり、いずれも作られた物の性質
ではなく作り方の性質である。この置き場所の帰結は §4 で扱う。

**T2 が T1 より強いこと自体は禁じない。** Battleship が Frigate より強く、かつ
高いのと同じ構造である。`docs/design/game-design.md` の非交渉的原則
「ゲーム時間・課金額は性能に影響しない」が禁じているのは**恒久的でアカウントに
紐づく優位**（スキルポイント、課金ブースト）であって、失える資産の経済ではない。

**代わりに制約するのは入手可能性である。T2 は、支払える者なら誰でも入手できな
ければならない。**

この線引きは EVE が 20 年の運用で 2 回学んでいる。

- **T2 ブループリント抽選（2003 Castor）。** 原本（BPO）を抽選で配ったため製造力が
  一部の集団に集中し、[市場に出さない・価格を吊り上げるという行動を招いた](https://wiki.eveuniversity.org/Invention)。
  CCP は 2006 年の Revelations で BPO を廃し、誰でも T2 を作れる Invention に
  置き換えた。
- **Technetium（2010〜2012）。** T2 の材料が地域偏在したため、保有勢力が
  ボトルネックを握り、[互いの moon を攻撃しないばかりか相互防衛まで約する
  カルテル（OTEC）](https://evenews24.com/2018/01/22/moments-in-history-otec/)が
  生まれた。CCP は 2013 年の Odyssey で
  [価値を最も希少な鉱物群へ分散させ](https://www.eveonline.com/news/view/resource-shakeup-blog)、
  地域的なチョークポイントを解体した。

**CCP はどちらの事例でも性能差を直していない。直したのは供給の集中である。**
2 例目は市場が十分に深い時期に起きており、「市場が大きければ誰でも入手できる」は
**売り手に売らない動機があると成立しない**ことを示している。territory ゲームでは
その動機は必然的に存在する。

供給保証の手段（生産経路を誰でも開けるようにするか、材料の供給源を分散させるか）
は territory の価値と綱引きになるため、9C の決定空間に送る。本 ADR は要件だけを
定める。

受け入れ条件は残す: **T1 編成が構成と判断で T2 編成に勝ち得ること。** これは差の
存在ではなく**差の大きさに上限を置く**制約であり、原則A（役割は代替できないこと
で定義される）・原則D（2〜10 隻の編成を基準にする）を保つために要る。

### 2. NPC ステーションは恒久的な床

NPC ステーションは T1 のみを即時に生産する。枠も待ち時間も持たない。これは暫定
措置ではなく恒久的な設計要素であり、次の 2 つを保証する。

- 9C が到達可能であること（構造物を作る場所がある）
- 全損したプレイヤーがループへ復帰できること

### 3. プレイヤー設置構造物そのものは T1

そうでなければ「T2 を作る場所を T2 でしか作れない」循環になる。

これは制約ではなく設計の重心を決める。**インフラは作るのは簡単、維持するのが
難しい。** ゲーム性は「建てること」ではなく「守り続けること」に乗る。

### 4. コストと Tier はレシピに属する

`SCRAP_METAL_COST_PER_PACKAGED_SHIP` の Rust const は廃す。`data/ship_types.toml` の
冒頭は既に "No Rust balance fallback exists" と宣言しており、経済で最も重要な数字が
Rust の `const` にあるのは現状の不整合である。

**移す先は出力アイテムで引くレシピであって、船種定義ではない。**

| | レシピが持つもの | アイテム定義が持つもの |
|---|---|---|
| 内容 | 入力（`ItemId` と個数）、Tier、所要時間 | 名前・クラス・base_stats・スロット |
| 判定 | 「どう作るか」の性質 | 作られた物そのものの性質 |

理由は 3 つある。

- **生産物が 2 種類目になった瞬間に機構が二重化する。** モジュールに生産経路を入れると
  `ModuleDefinition` に並行フィールド・並行 wire・並行 UI・並行拒否コードが要る。
  `BuildPackagedShipCommand` は現在唯一の建造コマンドで、出力型が名前に焼き付いている。
- **1 つの出力に 2 つの経路を持たせられなくなる。** EVE の T2 は BPO と Invention と
  いう別経路が同じ物を出す。§1 の入手可能性要件を満たす手段の候補がそれである以上、
  アイテム側に生産経路を 1 本だけ生やす形で塞いではならない。
- **アイテムに生産の事実を置くのは、`buildable: bool` で一度直した誤りの反復である。**

ただし**レシピ表を今すぐ作りはしない。** 現在の生産物は PackagedShip ただ 1 種類で、
表にしても行の種類が増えない。本 ADR が決めるのは置き場所だけであり、表を実際に出すのは
モジュール生産の ADR と同時とする。そこで初めて二重化を防ぐという実効が出る。

### 5. 時間のかかる生産は本 ADR では決めない

T2 の所要時間、枠数、襲撃時の進行中ジョブの扱い、枠の所有権——これらはすべて
**9C の決定空間**であり、本 ADR は「T2 は時間を要する」とだけ述べて具体を決め
ない。

この線引きには実装上の帰結がある。**T1 が即時である限り、進行中ジョブという
永続状態は存在しない。** ADR-0049 の `RecoveryDelta` にもチェックポイントにも
新しい状態は増えず、本 ADR の範囲では復旧契約に一切触れない。

## FBD-009 との関係

初稿では NPC ステーションにも時間のかかるジョブを置いており、オフライン中に
ジョブが完了することが FBD-009「no passive growth」に文字通り抵触していた。

**Tier を導入すると、この問題は基本ループから消える。** NPC ステーションの生産が
即時である以上、保証された復帰経路にオフライン進行は存在しない。時間のかかる
生産はプレイヤー設置インフラ側だけになり、それを持つかどうかは能動的な選択
（建てる・守る）の結果である。

したがって本 ADR は FBD-009 を変更しない。9C が時間のかかる生産を導入するとき、
オフライン完了を許すかどうかは 9C 側で改めて問われる。

> **2026-08-26 追記**: ここで立てた「破壊可能な設置資産に紐づく時間進行は受動成長
> ではない」という判定を、生産から**採取**へ広げる提案が [ADR-0057](ADR-0057-structure-mining.md)
> である。FBD-009 の改訂は本 ADR ではなく ADR-0057 が担う。

## 検討して落とした案

**NPC ステーションにも枠と待ち時間を置く（本 ADR の初稿）。** 基本ループに
オフライン進行が入り FBD-009 に抵触する。加えて「安全な床が支配的にならない」
ことを枠数と tick 数の調整に頼ることになり、設計ではなくバランスで解く脆い形
だった。Tier は同じ動機（インフラを建てる理由を作る）を構造で解く。

**T2 の供給を単一の territory 群に依存させる。** T2 がプレイヤー設置インフラ
からしか出ない以上、保有勢力には敵に売らない動機がある。EVE はこれを 2 回起こし
（T2 BPO 抽選・Technetium）、2 回とも供給の開放で直した。§1 の入手可能性要件は
この轍を踏まないためにある。負けた側が買い戻せないと、一時的な敗北が構造的な
敗北に変わる。

**生産をプレイヤー設置インフラ（9C）の機能にする。** 構造物自体が生産物なので
ブートストラップできず、全損からの復帰経路も失われる。

**生産ツリーを依存グラフとして構造化する。** 現在の生産は深さ 1 の星型である
（撃破 → `ScrapMetal` → `PackagedShip`、`ScrapMetal` が唯一の湧き口）。巡回検査・
依存の走査・原材料への総コスト畳み込みといったグラフ機構は深さ 2 以上でしか意味を
持たず、今書いても検証されない推測コードになる。レシピはフラットな表でよく、深さが
要るようになればデータが後から深くなるだけである。

なお `Disassemble` が戻すのは `PackagedShip` であって `ScrapMetal` ではないため
（`node/station_materialization.rs`）、`PackagedShip → ScrapMetal` の逆辺は存在せず、
無限増殖ループは構造的に塞がっている。可逆なのは `Ship ↔ PackagedShip` の 1 辺のみ。

**壁時計で所要時間を測る。** INV-005 / FBD-003 に反する。9C が時間を導入する
ときも tick で数える。

**採掘・放置収集を資源の絞りにする。** `（非交渉的）` として却下済み。

## 元の設計ブランチで先行実装したもの（本PRには含めない）

以下は `docs/adr-0056-production-jobs` ブランチの記録であり、mainの実装状況ではない。
本PRは設計文書だけを取り込み、建造コスト・wire・HUDの実装は含めない。

Tier そのものは未実装である（本 ADR は `proposed`）。一方 §4 の「コストを船種ごとの
データに置く」だけは、Tier の是非とは独立に**現在の欠陥を直す**変更なので先行して
実装した。

- `SCRAP_METAL_COST_PER_PACKAGED_SHIP` の Rust const を廃止し、
  `data/ship_types.toml` の `build_scrap_cost` へ移した。
- `buildable: bool` を `build_scrap_cost: Option<u64>` に置き換え、「建造可能だが
  値段が無い」状態を表現できなくした。
- 建造可能な船体を 3 種にした（Magpie 1 / Player Destroyer 3 / Player Cruiser 8）。
  既にデータにあった船体へ値段を与えただけで、新規の船体設計はしていない。
- 建造コストを wire に載せ、ビルドピッカーに表示するようにした。値段が見えなければ
  選ぶ材料が無い。
- `build_scrap_cost` は**船種定義に置いたままにしてある**。§4 の通りレシピ側が正しい
  置き場所だが、生産物が 1 種類のうちは表に分けても行の種類が増えない。移すのは
  モジュール生産と同時である。

この作業で**既存のバグが 1 件見つかった**。建造経路は船種が「存在するか」しか
見ておらず、`buildable` フラグを参照していなかったため、**NPC 専用船体が
プレイヤーに建造できた**。既存テスト 2 件が実際に NPC Frigate を建造しており、
それが露見の経緯である。`ShipTypeNotBuildable` の拒否を追加した。

## Open questions

- **T2 の供給をどう保証するか。** 生産経路を誰でも開けるようにするか（EVE の
  Invention 相当）、材料の供給源を分散させるか。territory の価値と綱引きに
  なるため 9C の決定空間。§1 の入手可能性要件を満たす手段が要る。
- **T2 に何を置くか。** `docs/design/game-design.md` のロール・ブレスト（§158）と
  勢力ボーナス（§183）が既に特化の軸を持っており、Tier がそれと二重に
  ならないか要検討。
- **T1 が張り合えるものであり続けるか。** 全損したプレイヤーは T1 までしか戻れ
  ない。T1 が形骸化すると「一度負けたら終わり」に戻る。9E-1 のプレイテストで
  見るべき最重要項目。
- **モジュールの生産。** 本 ADR は Tier を宣言するが、モジュールに生産経路が無い
  ままだと Market に流通するものが乏しい（別 ADR）。**これが §4 のレシピを実際に
  表へ出す契機である。** 同時に中間財を置くかどうかもそこで決まる。中間財の効能は
  ツリーの見栄えではなく**生産者を相互依存させること**で、現状は誰でも
  `ScrapMetal` → 船 を単独で完結できるため他人と取引する理由が無い。9D で Market を
  作った以上、ここを空のままにはできない。
- **T1 の希少性。** 撃破 1 隻 = Scrap 1 = 船 1 隻の 1:1 交換は、戦闘がちょうど
  自己完結する。Tier とは独立にコスト曲線の検討が要る。
