# ADR-0016 — プロジェクトの再定義: 「EVE を超えるゲーム」

> **ステータス注記**: 本 ADR は CLAUDE.md（権威ある運用規約）の改訂を伴う。
> CLAUDE.md 末尾の規則により、AI は CLAUDE.md を自律的に変更できない。
> 本 ADR は変更提案であり、CLAUDE.md への実適用は**人間の最終承認後**に行う。

## 背景

これまで CLAUDE.md §1 は「**ゲームを作っているのではない。研究基盤である**」と宣言してきた。
人間オーナーの判断により、プロジェクトのゴールを **「EVE Online を超えるゲームを作る」** に
再定義する。

この再定義は無からの拡張ではなく、次の 2 つの裏付けを持つ。

1. **dawn の分散基盤は EVE の最大の弱点を直撃する技術的優位である。**
   EVE は大規模戦闘時に Time Dilation（時間引き延ばし）で体験を犠牲にする。
   dawn の Single Shard / Raft / イベントソーシング / アンチ TiDi（INV-TiDi）は
   まさにこの問題を解くための設計であり、これは "研究テーマ" であると同時に
   **ゲームとしての最大の売り**になりうる。

2. **何が愛され何が嫌われるかは実証データで分かっている。**
   独立ツール `eve-research` で EVE 公式フォーラム等 **18,149 文書**を収集・分析した
   （docs/reference/eve-reference.md §6）。
   - 最も愛される: 命中の駆け引き（combat 否定率 34% = 最愛）・cap 戦・非対称リスク。
   - 最も嫌われる: **退屈なグラインド・AFK・スキルポイント育成・TiDi/lag**。
   → "超える" とは、愛される核を強化し、嫌われる要素を構造的に排除することである。

---

## 決定

### 1. ゴールの再定義

**ゲームを作ることがゴールである。分散シミュレーション基盤はその実現手段であり、
かつ競争優位（EVE が TiDi で諦めた大規模リアルタイム性）である。**
CLAUDE.md §1 の「ゲームを作っているのではない」を撤回し、両者の関係を上記に置き換える。

### 2. 4 本の柱（ビジョン）

「EVE を超える」を以下の 4 つの差別化で定義する。

1. **TiDi の無い大規模リアルタイム戦闘** — dawn の分散基盤を武器に、EVE が時間引き延ばしで
   諦めた「多数が遅延なく戦う」を実現する。技術的優位＝ゲームの売り。
2. **グラインドゼロの深い戦闘** — §6.2 の最大教訓「退屈なグラインドは大罪」を徹底。
   意図的判断（操船・適用・cap・タックル）だけで構成する。
3. **プレイヤー主導の世界** — プレイヤーが構造物・防衛・領域・経済を作る。
   Frontier の Smart Assembly に相当する「アクセス制御＝述語関数」を**非 Web3** で実装
   （eve-reference §7.3）。
4. **実損のある危険な宇宙** — 撃沈＝実損、Tackle（§7.4.1）で逃がさない非対称リスク。
   緊張感を体験の核に据える。

### 3. 維持する制約（"超える" ための武器）

以下は**ゲーム化後も不変**。むしろ EVE を超えるための核である。

- **反グラインド（FBD-009 は維持）**: スキルポイント制・時間経過の受動成長・課金加速育成・
  AFK 採掘は引き続き**禁止**。§6 でこれらは最も嫌われると実証された。これらの不在こそ差別化。
- **アーキテクチャ不変条件**: INV-001〜006 / INV-TiDi / INV-MOVE、および §1 の設計原則 1〜6
  （イベントソーシング・論理 Tick・Actor 分離・一方向依存）は**すべて不変**。
  これらは「TiDi の無い大規模戦闘」を成立させる土台である。

### 4. 解禁する制約（ゲーム化に必要）

- **FBD-008 を撤廃する。** `dawn-economy` / `dawn-character` / `dawn-inventory` /
  `dawn-ui` / `dawn-graphics` 等のクレート作成を**可**とする
  （ただし新規クレートは従来どおり個別 ADR + Dependency DAG 上の位置確定が必要 — §3/§9）。
- **「キャラクター」はエンティティとして解禁するが、「キャラクター育成（スキルポイント）」は
  解禁しない。** FBD-009 と両立させる（プレイヤー/パイロットの存在は可、時間/課金で強くなる
  受動成長は不可）。

### 5. 段階的拡張（Ship 中心のまま戦闘の深みから）

スコープは一気に広げない。**まず戦闘の深み**を、Ship を中心に据えたまま積む。
近期ロードマップ（eve-reference §7 の優先順位）:

1. **Tackle**（Transit/Jump 開始の拒否 = 逃がさない）← 最優先・新イベント不要
2. **Signature Resolution**（命中式の精緻化・TOML 数値で武器差別化が創発）
3. **Orbit / Keep at Range**（操船を戦術に・ADR-0015 の拡張）
4. **Logistics**（遠隔修理・集団戦の深み）
5. **資源シンク**（希少性で判断を生む。**受動採取は採らない** = FBD-009 維持）

各項目は**個別 ADR** を起票して着手する（挙動変更につき人間承認 — §1/§7）。
構造物・経済・キャラ等の世界拡張は、戦闘の深みが固まった後に別フェーズで検討する。

### 6. 実証データの位置づけ

`eve-research` のレポートを設計判断の**参照**とする。ただしレポートは挙動変更の根拠
そのものではなく、採用は個別 ADR + 人間承認を経る（従来どおり）。
docs/reference/eve-reference.md は「外部ゲームの事実と示唆の記録」であり仕様ではない。

## 却下した代替案

- **分散基盤を捨ててゲーム実装に専念する**: アンチ TiDi は "EVE を超える" 最大の武器
  （§6 で TiDi/lag は一様に嫌われると実証）。基盤を捨てるのは優位を捨てること。却下。
- **全制約を撤廃してフルサンドボックスに即時移行**: §6 でスキル育成・AFK 採掘・グラインドが
  最も嫌われると実証済み。反グラインド（FBD-009）は "超える" ための核なので維持する。却下。
- **再定義せず、機能ごとに個別 ADR で都度判断する**: ゴールが曖昧なまま機能が積み上がり、
  一貫性が失われる。ビジョンを明文化する方が以後の設計判断が速く・ブレなくなる。却下。
